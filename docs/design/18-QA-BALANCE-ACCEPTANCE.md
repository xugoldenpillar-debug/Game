# 18 — QA、数值平衡与完成验收标准

## 1. 质量目标

“完整”不是文件数量，而是玩家从启动游戏到通关主线都不存在阻断问题，并且核心战斗、武器、AI、存档、关卡和 UI 都达到一致质量。

发布阻断级问题：崩溃、无法继续任务、存档损坏、关键输入失效、Boss无法完成、关卡软锁、严重性能下降、资源无限复制、关键数据丢失。

## 2. 测试层级

### 单元测试
优先覆盖纯逻辑：伤害计算、护甲、爆头、掉落权重、技能修正、状态效果、弹药、存档迁移、任务条件。

### 集成测试
玩家+武器、AI+导航、任务+检查点、掉落+库存、技能+战斗属性。

### E2E
启动→新游戏→第一关→检查点→死亡重开→完成任务→基地→购买/装备→存档→刷新页面→继续游戏。

## 3. 战斗 QA 矩阵

每一种玩家状态至少测试：待机、跑、跳、蹲、滚、受击、倒地、处决、持枪、换弹。

每种武器类别测试：站立/移动/蹲射、空仓、换弹被打断、切枪、拾取替换、弹药为0、暂停恢复、检查点恢复。

## 4. AI QA

- 敌人不穿墙攻击。
- 丢失视野后搜索而非锁定。
- 近战正确占位。
- 掩体不重复占用。
- AI 受烟雾/闪光/EMP影响。
- 增援不会超 Encounter Budget。
- Boss 不读取玩家原始输入作弊。

## 5. 关卡 QA

每关测试：首次进入、检查点重开、死亡、退出重进、不同顺序完成可选目标、跳过可跳过剧情、低弹药状态、玩家走回旧区域、极端快速清怪、敌人未完全清理。

## 6. 存档 QA

必须覆盖：
- 新存档。
- 多槽存档（若实现）。
- 版本升级迁移。
- 缺字段/旧字段。
- 非法数据回退。
- 刷新页面和浏览器重启。
- 检查点写入中断时不破坏已有完整存档。

建议采用临时写入→校验→替换的方式减少损坏概率。

## 7. 性能测试场景

建立专用 `perf_arena`：20敌人、持续机枪、爆炸、火焰、Ragdoll、粒子同时出现。记录 FPS、frame time、active bodies、projectiles、particles、AI update cost。

目标：主流桌面浏览器 1080p 默认设置稳定接近 60 FPS。低配模式减少粒子、尸体和环境装饰，而不是删除关键提示。

## 8. 数值基准

### 玩家
初始 HP 100。基础敌人普通攻击通常造成 8–18；强攻击 20–35；Boss 高伤明确招式 30–55。避免Normal难度频繁满血秒杀。

### Time-to-kill
普通敌人：有效输出下约 0.5–3 秒。
重装/精英：3–8 秒。
小Boss：20–60 秒。
章节Boss：目标 2–5 分钟，首次挑战可更长。

## 9. 武器平衡

不以纯 DPS 排名。综合：有效DPS、爆发、弹药效率、距离、移动能力、控制、穿甲、风险。

测试模板：对无甲单体、重甲单体、3人群体、远距离目标、移动目标分别记录表现。

## 10. 难度

Story：更宽松的敌人伤害和资源，Boss机制保留。
Normal：设计基准。
Hard：更聪明、更积极、资源略少，数值中度上调。
Extreme：面向熟练玩家，敌人组合与机制更严苛。

禁止仅用“敌人生命×3、伤害×3”定义高难度。

## 11. 输入延迟与手感

按键到可见动作响应应尽量在同帧/下一逻辑帧发生。可缓存连击、跳跃和闪避输入。禁止为了动画完整性让玩家感觉按钮失灵。

## 12. 发布验收 Gate

### Vertical Slice Gate
一关、1 Boss、5敌人、6武器、核心动作、检查点、存档。必须先达到“反复玩仍然有爽感”。

### Alpha Gate
8章骨架全部可通、主要系统齐全、临时素材允许、无主线阻断。

### Beta Gate
全部48主线、支线主要内容、武器/技能/敌人接近最终，开始内容锁定。

### Release Candidate Gate
无已知 blocker/critical；性能达标；存档迁移验证；主线从零完整通关至少多轮；浏览器兼容验证。

## 13. Definition of Done

一个功能只有在以下条件都满足才算完成：实现、数据化、错误处理、调试手段、关键测试、音画反馈、存档兼容（若相关）、文档更新、通过验收标准。
